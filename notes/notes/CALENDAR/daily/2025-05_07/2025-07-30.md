There is a slight problem with calculating the EPA emission tier recognition ratio. From the conversation in #dev, I understood the value should be calculated as:
- Select rows, where human recognized the Locomotive ID and where the ID matches the prediction. Let's say we got `N` samples that satisfy these conditions.
- Then, we attempt to find emission tier for them. Let's say we found `R`  records.
- The resulting ratio is then `R/N`

My questions are:
**1:** The first sample of size `N` can contain multiple sightings of the same locomotive. Locomotives without/without emission tiers that occur often makes the number lower/higher proportionally to the number of sightings. Is this correct, or do we want to de-duplicate first? The number would then be percentage of locomotives that we spotted at least one with available emission tier record.

**2:** To match sightings with the Umler database, we need two car features: Locomotive ID and Painted rail ID. We can predict both, however the painted rail ID is not always visible and as I understand, annotators don't even rate them.

Ratio of available emission tiers for the data where algo prediction matches human and data is not missing.

	What percentage of equipment_ids have emission tier filled in UMLER db,
	given that the human rating of car_id matches algo and the painted id prediction is not missing?
	P(emission tier | human rated car_id && human.car_id == algo.car_id && algo.painted_id)

	- the API call returns grouped data but we would need to have an information per locomotive sighting.

Is this the best approach to satisfy the expectations?
	- People automatically assume there is a connection between epa_tier_ratio and locomotive id ratio.
